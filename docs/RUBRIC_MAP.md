# Rubric map

Where each judging criterion is evidenced in this repository.

| Criterion (20% each) | Evidence |
|---|---|
| Technological implementation | Synthetic data creation: `src/bts/sim/engine.py` (zone Markov chain, hidden momentum, per-shot xG spread), calibrated by `scripts/realism_check.py` against six target ranges (table in README). Hero technologies: Microsoft Agent Framework crew (`src/bts/insights/crew/`) on Microsoft Foundry structured outputs (`src/bts/insights/foundry.py`), OpenTelemetry traces in Application Insights (`src/bts/telemetry.py`), Azure Container Apps (`infra/deploy.sh`, `Dockerfile`), Azure Cosmos DB (`src/bts/store/profiles.py`), GitHub Copilot and Azure MCP workflow files (`AGENTS.md`, `.github/copilot-instructions.md`, `.vscode/mcp.json`). Practices: 174 tests written first (`tests/`, `web/src/lib/*.test.ts`), ruff, typed TypeScript, CI (`.github/workflows/ci.yml`). |
| Agentic design and innovation | A four-role Microsoft Agent Framework crew (`src/bts/insights/crew/`): a tactical analyst with tools over the shared match context, a narrator per audience and language, a fact checker with a deterministic `check_numbers` tool, and a producer executor that re-checks every number and plans the overlay. Sequential workflow with the conversation flowing between roles, one retry with the issues attached, bounded turns, and a fallback chain (crew, simple pipeline, templates) in `src/bts/insights/pipeline.py`. Every insight carries a per-agent trace shown in the UI; every run is traced to Application Insights. Plus the question desk (`src/bts/insights/qa/`): a grounded Q&A agent with eleven tools over the live session, conversation memory, a deterministic citation check that decides the `verified` badge, and an honest `not in the data` answer when the tools cannot answer (`docs/ASK_THE_MATCH.md`). |
| Real-world impact and applicability | Timed, machine-readable overlay cues for broadcast rendering (`GET /api/matches/{id}/cues`), a question desk any second-screen app can call (`POST /api/matches/{id}/ask`), studio and streaming use cases in the UI, one-container deployment with secrets and scale rules (`docs/DEPLOY.md`), cost notes (`docs/FOUNDRY.md`). |
| User experience and presentation | Live UI at 1280×720: scoreboard, pitch monitor with lower third, side panel and ticker, stats rail with momentum gauge, insight feed with verified and source badges, "Ask the match" panel with suggested questions, citations and status badges, profile and language switch, full-time recap (`web/src`). Design notes in `web/DESIGN.md`. |
| Adherence to category (Best Use of Microsoft Foundry) | Every agent turn, insight, answer and recap is a Foundry structured-output call: the crew and the question desk through Agent Framework's `OpenAIChatClient` on the Foundry resource, the simple pipeline through one `LLMClient` seam; the UI labels model output as `Agent crew` or `Foundry` and shows `verified` only when the checks passed. Setup and SDK notes in `docs/FOUNDRY.md`. Also entered for Best Multi-Agent Orchestration (`docs/AGENTS_CREW.md`). |

Stage One (viability): the project fits the theme (synthetic football events to explainable match intelligence) and applies the required technologies (Foundry, Agent Framework, Container Apps, Cosmos DB, Application Insights, GitHub Copilot and Azure MCP in the workflow).
