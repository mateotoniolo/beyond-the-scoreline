# Synthetic match data

Every match in Beyond the Scoreline is generated by our own seeded simulator. **All clubs, players, venues and competitions are fictional.** No real league data is bundled, derived or redistributed.

## Event

| Field | Type | Meaning |
|---|---|---|
| `event_id` | int | Sequential id within the match |
| `match_id` | str | `m{seed}` |
| `period` | 1 or 2 | Half |
| `t` | float | Seconds since kick-off of the match (second half starts at the first half's end) |
| `clock` | str | `mm:ss`, minutes may exceed 90 |
| `team_id` | str | Team performing the action (for `pressure`, the pressing team) |
| `player_id` | str or null | Player performing the action |
| `type` | enum | See taxonomy below |
| `subtype` | str or null | e.g. pass: `short`, `long`, `cross`, `through`; shot: `open_play`, `header`, `volley`; duel: `tackle`, `aerial` |
| `start` | `{x, y}` | Where the action starts, 0 to 100 on both axes |
| `end` | `{x, y}` or null | Where the ball ends up (passes, carries, shots) |
| `outcome` | enum or null | `success`, `fail`, `goal`, `saved`, `blocked`, `off_target` |
| `tags` | list[str] | e.g. `key_pass`, `assist`, `counter_attack`, `under_pressure`, `final_third_entry` |
| `meta` | dict | Numeric details: `xg`, `pass_distance` (m), `pass_difficulty` (0 to 1), `shot_speed` (km/h), `ball_speed` (km/h) |

Schemas: `docs/schema/event.schema.json`, `docs/schema/match.schema.json` (generated by `uv run python scripts/export_schema.py`).

## Coordinates

Both axes run from 0 to 100, as in the Wyscout public dataset convention. The team in possession always attacks from left (`x = 0`) to right (`x = 100`); the simulator flips coordinates for the away team's possessions so consumers never need to know which goal is which. Distances in `meta` assume a 105 m × 68 m pitch.

## Event taxonomy

Type names follow the [kloppy](https://github.com/PySport/kloppy) standard event model: `pass`, `carry`, `shot`, `duel`, `interception`, `clearance`, `recovery`, `miscontrol`, `ball_out`, `foul`, `goalkeeper`, `pressure`, `substitution`, `card`, plus `period_start` and `period_end` markers.

## Mapping to Wyscout names

| Ours | Wyscout |
|---|---|
| `type` | `eventName` |
| `subtype` | `subEventName` |
| `tags` | `tags` |
| `t` | `eventSec` (ours is match-relative, Wyscout's is period-relative) |
| `period` | `matchPeriod` (`1H`, `2H`) |
| `player_id` | `playerId` |
| `team_id` | `teamId` |
| `start`, `end` | `positions[0]`, `positions[1]` |

The mapping exists so the format is recognisable to analysts; no Wyscout data is included.
